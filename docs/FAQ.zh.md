## 一、关于"听不见声音"

### Q1. 装了插件，能出图，但 AI 说"没听见声音 / 听不到台词"，是我哪里错了？

不是 bug，是**转写没配**。

插件出图完全不需要 ASR。只有"想知道视频里说了什么"才需要它。没配的时候清单里
`transcript="no-key"`，意思很明确：**我压根没去听**（不是"听了但没人说话"）。

**怎么办**：跑 `node bin/doctor.mjs`，看第 3 段。二选一：

```json
// 本机服务（免费，不需要 key）
{ "baseUrl": "http://127.0.0.1:8000/v1" }
```

```json
// 云端（要 key，按量计费）
{ "key": "sk-...", "baseUrl": "https://api.siliconflow.cn/v1",
  "model": "FunAudioLLM/SenseVoiceSmall" }
```

写在 `~/.dsh/asr.json`。**0.5.0 起改完即生效，不用重启。**

### Q2. 我配了本机服务，它还要我填 key？

本机地址（`127.0.0.1` / `localhost` / `[::1]` / `0.0.0.0`）**不需要 key**，这是设计。

如果它仍说没配，多半是 `baseUrl` 写了 `http://127.0.0.1:8000`（少了 `/v1`）导致被当成未知端点，
或者环境变量 `DSH_ASR_BASE_URL` 指到了别处（**环境变量优先级高于 `asr.json`**）。

`node bin/doctor.mjs` 第 3 段会打印"实际在用的 baseUrl 和它的来源（env / file / default）"。

### Q3. 台词全程返回 `asr-empty`，但视频里明明有人说话

`asr-empty` = **跑了 ASR，但没听出内容**。三种常见原因：

1. **下载下来的文件没有音轨**（见 Q5）。先确认：`node bin/asr-check.mjs 视频.mp4` 第一行有没有 `NO AUDIO`。
2. **说话是重叠的/尖叫/唱歌**。ASR 会把非语音段当噪声丢掉（这是故意的，避免把歌词当台词）。
3. **片段太短**。几十毫秒的气口听不出来。

### Q4. 转写结果和 B 站的 AI 字幕差很多，有的地方还多一句少一句

**设计如此，不是错。** 优先级是：**影片自带字幕轨 > B 站字幕 > 我们自己听（ASR）**。

- 有字幕轨时，我们抄的是作者原话，几乎不会错；
- 只有没字幕时才去听，听出来的东西对**术语、人名、方言、重叠说话**都不稳。

要引用原话（做字幕、写文案），就明确让它"用字幕轨"或"zoom 到那一格再核对"。

## 二、关于安装与"装了但用不了"

### Q5. 下下来的视频没声音，mp4 正常能播但音轨是空的 ✅

原因：yt-dlp 合流音视频要调用 ffmpeg，而 DSH 桌面版把 ffmpeg 放在
`~/.dsh/tools/ffmpeg/bin`（**不在 PATH 上**）。找不到 ffmpeg 时 yt-dlp **不报错**，
静默只下视频轨，退出码还是 0 —— 于是你拿到一个没声音的 mp4，谁都没喊。

0.5.0 起：下载时会自动把解析到的 ffmpeg 路径通过 `--ffmpeg-location` 传给 yt-dlp。
另外只要 `node bin/doctor.mjs` 第 1 段是绿的，就不会再遇到。

### Q6. 装完 ffmpeg 还是报错，重启 DSH 才好

**这不是 bug，是必须做的动作。** DSH 在启动时把"有没有 ffmpeg"记在进程里，
装完不重启的话它仍然按"没有"走。表现就是一直卡在 ffprobe。

**规矩**：凡是装/改了 ffmpeg、yt-dlp 这类外部程序，**完整退出 DSH 再打开**。

### Q7. 贴链接下载很慢、下到一半清零重来、越下越慢 ✅

0.4.x 的 bug：下载失败时把整个缓存目录 `rm -rf` 掉，于是网络一抖就从头再来，
多次失败后表现为"越下越慢"。0.5.0 起：带 `--continue` 断点续传，失败**不删目录**，
残留的 `.part` 由缓存清理按时间回收。

还是慢的话，更省事的办法：**自己先把视频下下来，再把本地文件丢给它**。

### Q8. 改了 `asr.json` 完全没反应，得重启整个 DSH ✅

0.4.x 的 `ASR_DEFAULTS` 是模块加载时的一次快照。0.5.0 起按文件修改时间热加载，
改完下一次调用就生效。

### Q9. 改完台词设置再跑，还是旧的转写（吃到旧缓存）✅

转写缓存的键里现在包含：ASR 地址、模型、切片长度、`transcript` 模式、热词。
这几项任一变都会重新转写。0.4.x 的键缺 `transcript`，所以"先关掉台词跑一次、再打开"会命中旧结果。

## 三、关于"工具参数没生效"

### Q10. `video_locate` 一调就报 `ReferenceError: recallSegments is not defined` ✅

0.4.1 的 bug：`src/index.js` 用了 `recallSegments / matchSegments / formatMatches` 却没
`import './locate.js'`。0.4.4 起已修（导入在文件顶部），不需要再手工补。

### Q11. `video_zoom` 的 `minGap` 改了没用，永远按 1.2 秒走 ✅

0.4.3 的 bug：zoom 的 handler 是逐个字段手写 `runStoryboard` 参数的，列表里漏了 `minGap`，
`schema` 里声明了、也校验了，但到参数装配那一步就丢了（**"写了没接线"**）。

0.5.0 起三个入口（storyboard / zoom / watch）的参数统一由 `board.js` 装配，只有一份定义。
`test/schema-audit.test.mjs` 会扫 `args.X` 并断言都在 schema 里，防止再漏。

### Q12. 我要 16 格，实际只出了 8 格，头一行却写 `16 cells` ✅

两件事：

1. **出不到 16 格**是正常的：格与格之间要留最小间隔（默认 1.2 秒），15 秒的片子最多拆 8 格。
2. **头一行写 16 是错的**：0.5.0 起头一行写**实际格数**，被卡住时追加 `(asked 16)`，
   例如 `grid="8 cells x 1 image(s) (asked 16)"`。

### Q13. 有的宿主里报 `TypeError: Cannot read properties of undefined (reading 'length')`，看起来像 ffprobe 坏了 ✅

真凶是 `promisify(execFile)`：某些宿主的 `promisify` 会丢掉 execFile 的 custom symbol，
只把 stdout 字符串交回来，于是取 `stderr.length` 就炸。

0.5.0 起 probe 改成**回调式 `execFile`**，不再经过 `promisify`。

## 四、关于"为什么只给这么几格"

### Q14. 104 秒 53 个镜头，只给 4 格，是不是太抠了？

这是 **0.4.4 的默认值**，不是 0.5.0 的行为。0.4.4 对"字/秒 > 3"的口播片会一路降档，
沧野那支（299s / 122 镜）就被压到 4 格 = 只覆盖 126 个镜头的 3%。

0.5.0 的默认格数按"每格不超过 90 秒 + 镜头数"算，同一支片子给 9 格；
明说"要 16 格"也给得出。

### Q15. 一条 90 秒的 PV，为什么给 9 格却塞了 36 个小画面？

那是**二重细分**：一格里面再切 2×2，专治"一个格子里其实有好几个镜头"。

⚠️ 但这条已经在 0.5.0 收紧：**子帧小于 200×112 就不摊**。因为实测 123×68 和 165×92
的字幕都认不出来——摊开反而降低信噪比。所以现在 3×3 / 4×4 的布局不再摊，只有 2×2 才摊。

## 五、关于钱

### Q16. "一分钱看五分钟"到底怎么算的？

按**图**算，不是按分钟算：一张宫格图 ≈ 384 token（DSH 宿主口径，每图约 384）。
5 分钟的片子默认出 1 张 ≈ 0.011 元；66 分钟的讲座出 4 张 ≈ 0.047 元。

所以"越长越贵"其实是"**张数越多越贵**"。想省钱：分段看（只让你关心的那 10 分钟出图），
别一次要全片。

### Q17. 为什么长片的张数是它自己定的，我不能指定？

可以指定（`sheets` 参数，1~16）。但默认档是按"每张塞多少帧"算的，比手填更省。
不建议为了省钱把 66 分钟压成 1 张 —— 每格 4 分钟，等于没看。
