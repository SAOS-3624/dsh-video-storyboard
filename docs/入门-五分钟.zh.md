# 五分钟上手（写给第一次用的人）

> 目标：**从"刚装完插件"到"看见第一张分镜图"**，中间不查任何别的东西。
> 每一步都写了"你应该看到什么"。看到的东西不一样 → 跳到文末「对不上怎么办」。
>
> 深度安装（多平台、PATH 细节）：看 `INSTALL.zh.md`。
> 各种报错的原话：看 `FAQ.zh.md`。

---

## 0. 先认清一件事

这个插件**不"看"视频**。它做的是：**每隔一段抽一帧，拼成一张宫格图**，再把每格的时间码和台词
排成清单，一起交给 AI。

所以有三件事是**正常现象，不是 bug**：

| 你可能会想 | 实际是 |
|---|---|
| "它说没听见声音" | 转写没配。出图不需要它，配了才有台词（见第 3 步） |
| "一分钟的片子只给 4 格" | 格数是按内容算的。想要更多就明说"要 16 格" |
| "台词跟 B 站字幕不一样" | 我们是**听**音轨，不是抄字幕。有字幕轨时才会优先用字幕 |

---

## 1. 先跑一次自检（30 秒，最省事的排错）

在插件目录里执行：

```bash
node bin/doctor.mjs
```

**你会看到五段**：ffmpeg / yt-dlp / ASR / 缓存目录 / 下一步。

- 全是 ✅ → 直接跳到第 4 步
- 有 ❌ 或 ⚠️ → 每条下面都有一行 `→`，照着做就行

> 这一步能挡掉 80% 的"装了但用不了"。先跑它，别先怀疑插件坏了。

---

## 2. 装 ffmpeg（唯一的硬性依赖）

**Windows：**

```powershell
winget install Gyan.FFmpeg
```

**装完必须做的一件事：把 DSH 完全退出，再重新打开。**

> 这一步是用户踩得最多的坑：ffmpeg 装好了、终端里也能跑，但 DSH 是装之前启动的，
> 它记着的还是"没有 ffmpeg"。表现就是**一直卡在 ffprobe**，重启一次就好了。

验证：新开一个终端，敲 `ffmpeg -version`，能打印版本号就算成功。

> DSH 桌面版自己带了一份 ffmpeg（在 `~/.dsh/tools/ffmpeg/bin`）。插件会先找它，
> 找不到再找 PATH。所以**通常你什么都不用配**——只要 doctor 第 1 段是绿的。

---

## 3. 配台词（可选，但九成人想要）

**不配也能用**：照样出图、照样有时间码，只是清单里没有台词，AI 只能看画面。

有两个选项，选一个就行：

### 选项 A：本机服务（免费、不联网、不用 key）

前提：本机已经跑着一个兼容 OpenAI `/audio/transcriptions` 的服务（比如 funasr、whisper.cpp 的 server）。

在 `~/.dsh/asr.json` 写：

```json
{ "baseUrl": "http://127.0.0.1:8000/v1" }
```

> 本机地址（127.0.0.1 / localhost）**不需要 key**，这是设计如此，不是漏配。

### 选项 B：云端（要 key、按量收费）

```json
{
  "key": "sk-你的key",
  "baseUrl": "https://api.siliconflow.cn/v1",
  "model": "FunAudioLLM/SenseVoiceSmall"
}
```

### 改完怎么生效

**不用重启。** 0.5.0 起，`asr.json` 是每次现读的（按文件修改时间判断），改完下一次调用就是新配置。

> 0.4.x 时代这条是真的要重启整个 DSH，现在不用了。

验证：

```bash
node bin/asr-check.mjs "D:/随便一个有人说话的视频.mp4" --from 10 --seconds 12
```

只花十几秒音频的钱。能打印出几句台词就说明通了。

---

## 4. 第一次跑

### 方式一：直接把文件丢给 AI（最常用）

在聊天框里说：

> 帮我看一下 `D:/视频/xxx.mp4`，出个分镜

AI 会调用 `video_storyboard`，然后**给你一张图**（宫格）+ 一段文字（每格时间码、台词、切点数）。

### 方式二：自己敲命令（不经过 AI，排查用）

```bash
node bin/storyboard.mjs "D:/视频/xxx.mp4" --out out.png --manifest out.json
```

**你应该看到：**

```
[probe] 1920x1080 30.00fps 299.41s audio
[scan] 7482 帧 → 122 个切点（阈值 12，自适应 3 个密集段）
[plan] 9 格 × 1 张 — 299s、123 个镜头 → 9 格 × 1 张（≈33s/格）
[sheet] D:/.../out.png  1009x620  3x3  cell≈331x184
[done] 8993ms
```

四行分别对应：**读到了什么 → 找了多少个镜头 → 决定切几格几张 → 出了一张多大的图**。

### 方式三：贴链接

直接说"看这个 https://www.bilibili.com/video/BVxxxx"。

- 需要 yt-dlp（doctor 第 2 段）
- **第一次会慢**：要先把视频下载到本地缓存（几百 MB 的片子可能几分钟）
- 断了不用从头：下载是断点续传的，再跑一次会接着下

> 下载很慢时更省事的办法：**自己先把视频下下来，然后把本地文件丢给它**。

## 5. 怎么看结果

AI 回给你的清单大致长这样：

```
<storyboard duration="299.41" grid="9 cells x 1 image(s)" tokens="384 ..." cuts="122 ...">
cell 1 (r1c1) = 00:00.00-00:33.30  frame@00:16.65
  台词：评价一个镜头的好坏，一般来说有两个维度……
```

- `grid="9 cells x 1 image(s)"` = 这张图有 9 格，是 1 张
- `frame@00:16.65` = 这一格代表的那一帧在第 16.65 秒（**想要更清楚就让它 zoom 到这一格**）
- `tokens="384"` = 这张图大约花多少 token（DSH 宿主按"每张图 384"计费）

**想让某一段看得更细**，就说："把第 5 格放大看看"。它会调 `video_zoom`，只重出那一小段。

---

## 6. 三条使用建议（都是血泪）

1. **别一上来就要 16 格、4 张。** 先默认出一张，看清楚结构，再针对某段要求细看。
   格数堆满会导致每格很小——**格子越小，字越看不清**，这是像素算术，不是算法能救的。
2. **长片先粗后细。** 一小时的片子先让它出个总览（可能 3~4 张图、上千 token），
   再从"我想看第 20~25 分钟"往下钻。一次要全片细节，token 会炸。
3. **它给的台词是听出来的。** 术语、人名、专业词可能错。要引用原话时，
   让它 zoom 到那格再核对一遍。

## 7. 对不上怎么办

| 现象 | 先做这个 |
|---|---|
| 报 `ffmpeg not found` / 卡在 ffprobe | 装 ffmpeg，然后**完整退出 DSH 再打开** |
| 能出图但"没有声音" | 第 3 步没配。跑 `node bin/doctor.mjs` 第 3 段看它怎么说 |
| 报 `yt-dlp not found` | 只影响贴链接。装 yt-dlp 或改用本地文件 |
| 下载到一半断了、越下越慢 | 再跑一次（断点续传）；或自己下好再丢文件 |
| 改了 `asr.json` 没反应 | 确认改的是 `~/.dsh/asr.json`；0.5.0 起改完即生效，仍无效就跑 doctor 看它读的是哪份 |
| 格数比我要的少 | 片子短 / 镜头少时会被最小间隔卡住；清单里会写 `(asked 16)`，那就是被卡了 |
| 台词比字幕少几句 | 有字幕轨时用字幕；没有才走 ASR，ASR 会漏气声/重叠说话 |

还是不行？收集三样东西发出来，基本能一次定位：

1. `node bin/doctor.mjs` 的完整输出
2. 出错那条命令的**完整**输出（别截中间）
3. 素材：多长、有没有说话、是本地文件还是链接
